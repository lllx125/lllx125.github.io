TL;DR A Julia package for the SciBmad project that provides physical constants, subatomic particle properties, and atomic isotope data from CODATA, NIST, and PDG. One @APCdef macro call fixes units and numeric types up front, so exported functions are type-stable and core calls run in under 1 microsecond.

Motivation

Beam simulation needs constants that are fast, stable, and traceable

1Context

  • Bmad, developed at Cornell’s Laboratory for Elementary Particle Physics, has long been a key framework for simulating charged-particle dynamics.
  • SciBmad is a new Julia-based simulation environment that uses Julia’s performance, parallelism support, and native multiple dispatch.
  • Within SciBmad, this package fills the need for fast and stable access to physical constants.

2The performance trap

  • Simulations want different unit systems and numeric types, but custom units and types usually lead to type instability and slow run time.
  • The typical approach is a getter that converts units and type at run time. This adds computation and makes the function type-unstable.
  • If the return type is not decided at compile time, the compiler cannot optimize the program, which costs more memory and time.

3Existing packages

  • PhysicalConstants.jl, one of the most widely used Julia packages, provides reliable static constants with uncertainty support.
  • AtomicAndPhysicalConstants.jl adds a direct interface for constants and an option to customize units and variable types.
  • Its Species type wraps particle attributes such as mass and charge for simpler access.

Design

Aggregated data, configured once by a macro

1Data sources

CODATAconstants

Loads the most recent release by default (currently CODATA 2022); earlier releases such as CODATA 2018 stay available through versioned submodules.

NISTisotopes

NIST keeps no history of its isotope datasets, so isotope data reflect the most recent release.

PDGpions

π0 and π± properties are downloaded directly from the PDG API.

2@APCdef keywords

KeywordChoices
unitsystemACCELERATOR, MKS (SI), CGS, or a custom five-tuple of Unitful units
unittypeFloat64, Unitful.Quantity, or DynamicQuantity.Quantity
nameName of the named tuple holding the constants (default APC)
tupleflagfalse defines constants as global variables in the current namespace

Invoked once during package initialization; a second invocation raises an error. It sets units and types for all constants and for Species mass and charge.

3Generate, don’t convert

ConfigureChoose units and numeric type in a single macro call
↓
GenerateConstants and getters such as massof(), chargeof() are written into the namespace with a fixed unit and type
↓
RunNo unit conversion; return types are known at compile time

Trade-off: the macro call itself is slower, but the program is fast at run time.

Species

One type for particles and atomic isotopes

1Constructing a Species

  • Species(::String) takes an OpenPMD-standard particle name. Fields: name, mass, charge, spin, moment, iso.
  • Subatomic particles: exact, case-sensitive names; antiparticles use the “anti-” prefix. 14 subatomic particles are supported.
  • Atoms: an atomic symbol, an optional isotope mass number (prefix 13C or superscript ¹³C), and an optional charge (+, ++, +n, or negatives).
  • No isotope given: mass is the abundance-weighted mean (per NIST). No charge given: neutral.
  • Null species: a placeholder for a field that must exist but is not yet assigned.

2Properties and derived quantities

Getters return mass m, charge q, atomic number Z, and spin S in the units and types chosen by @APCdef. Derived quantities:

g = 2mμSqGyromagnetic ratio; μ is the magnetic moment
ga = g − 22Gyromagnetic anomaly, for leptonic species
gn = gZmpmNucleon-normalized g-factor, for baryonic species; mp is the proton mass

Usage

From configuration to particle data in a few lines

1Constants

Session A · defaults (ACCELERATOR units, Float64)
julia> using AtomicAndPhysicalConstants julia> @APCdef julia> APC.C_LIGHT # m/s 2.99792458e8 julia> APC.E_CHARGE # elementary charge 1.0 julia> e = Species("electron") julia> massof(e) # eV/c² 510998.95069
Session B · Unitful, MKS, constants as globals
julia> @APCdef unittype = Unitful unitsystem = MKS tupleflag = false julia> E_CHARGE 1.602176634e-19 C

2Species strings

Species("anti-proton") Species("13C+") # C-13, +1 Species("¹⁵N³⁻") # N-15, −3 Species("Al+3") # mean Al, +3 Species("Null") # placeholder

Two separate sessions: @APCdef is called once per session, so each configuration starts fresh.

Examples and outputs are taken from the package documentation for the @APCdef releases (v0.7.2 README; units and species pages, v0.7.2–v0.8.2). Comments are added.

Quality control and performance

Tested in CI, benchmarked for type stability

1Testing

  • An extensive, modular test suite validates @APCdef configurations and Species constructor parsing rules.
  • All tests run on GitHub Actions as a continuous integration (CI) workflow.

2Benchmarking

Goal: ensure type stability (a variable’s type is decided at compile time) and improve speed.

  • BenchmarkTools.jl measured memory allocations and execution time of @APCdef, species construction, and getters such as massof() and chargeof().
  • JET.jl detected and eliminated dynamic dispatches and type instabilities.

3Results

< 1 µs
Core function run time, including @APCdef and Species()

Summary

A type-stable, unit-aware foundation for SciBmad

1Takeaways

  • A type-stable, unit-aware interface to physical constants.
  • Authoritative datasets with pinnable historical versions give numerical traceability.
  • One macro configures unit systems and variable types, integrating Unitful.jl and DynamicQuantities.jl.
  • Species simplifies work with subatomic particles and isotopes.

2At a glance
