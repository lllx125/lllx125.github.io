System-Prompt Anchoring with Cross-Attention Layers

Lixing Li · Cornell University
TL;DR — Cross-Attention Layer (CAL) blocks give a frozen causal decoder a dedicated route to the privileged system-prompt span. A ten-configuration sweep at 1.5B shows that where the route is inserted matters: later placements are generally more effective and parameter-efficient. At 8B, the selected late8th configuration improves instruction adherence and many-shot jailbreak resistance over a parameter-matched baseline, with task-dependent effects elsewhere.

Motivation

System rules and untrusted text get equal priority

1Instruction hierarchy

  • Deployed LLMs rely on a system prompt for behavioral constraints and safety rules.
  • Standard causal self-attention treats privileged instructions and untrusted user data with equal priority.
  • Prompt injection: adversarial user inputs overwrite the system prompt’s rules and hijack the model’s objective.
  • Context drift: system instructions gradually erode over extended or multi-turn sequences.

2Related approaches

  • Behavioral alignment: SecAlign and StruQ use preference optimization and structured queries; Instruction Hierarchy training teaches models to prioritize privileged instructions.
  • Representation-level: AIR injects hierarchy signals into intermediate representations; ASIDE separates instructions and data at the embedding level.
  • Cross-attention routes: encoder–decoders, RETRO, Flamingo and BLIP-2 condition on a separate source; ControlNet uses zero-initialized branches on a frozen backbone.

3This paper

CAL blocks source keys and values from a privileged span within the same causal sequence. The focus is not a new cross-attention architecture, but how injection depth affects use of that route.

Q1. Does a dedicated route to the system prompt change performance on security and instruction-following tasks?

Q2. How does the placement of the injected blocks affect that performance?

Method

A CAL block: cross-attention into the system-prompt span

1Architecture

Blocks are inserted after selected decoder layers. Each lets the full residual stream query the system-prompt span, then applies a SwiGLU feed-forward sublayer; the ordinary self-attention and residual paths stay intact.

  • Backbone frozen; only CAL parameters are trained.
  • Output projections WO, WD are zero-initialized, so every inserted block is an identity map at initialization.

2Causal cross-attention

Queries come from the full sequence; keys and values only from the system span [s, e), after RMSNorm:

Q = XWQ,  K = X[s:e]WK,  V = X[s:e]WV

A query at position i may attend to span slot j only if j ≤ i − s: system tokens see only their causal prefix, while later user and generated tokens see the whole span, with no future-token leakage.

X′ = X + Attn(Q, K, V, M)WO
X″ = X′ + SwiGLU(RMSNorm(X′))WD

Span bounds and CAL keys/values are computed at prefill and cached for decoding.

Results · 1.5B placement sweep

Placement matters, and later is generally better

MMLU and GSM8K: pp change vs. Base; other panels absolute. Blue = accuracy (higher is better); red = attack success rate (lower is better).

1Depth effect

  • Sparse late placements generally offer the strongest performance–parameter trade-off; early or dense insertion performs poorly on several instruction-following and security tasks.
  • No placement dominates: different depths lead IFEval, Glaive FC, IH-Challenge and InjecAgent.
  • Within late placements, distributing a few blocks beats concentrating the intervention in one final block.

2Matched controls

  • LoRA loses substantial MMLU and GSM8K performance and sharply increases attack success on InjecAgent and MSJ.
  • late8th vs. ParallelMLP: comparable on formatting and extraction, stronger on SysBench and Glaive FC, narrowly better on all four security evaluations.

Mechanistic analysis

How much does each inserted block update the residual stream?

Cell = 100 · E‖X″ − X‖₂ / E‖X‖₂ for one configuration and layer; gray = no inserted block.

Within-window pattern

Updates spike at the first available block, fall through the middle, and rise toward the end, for earlythird and midthird alike.

Late configurations

Strong late configurations keep updates above 1% near the end of the network; ParallelMLP has a similar late-stage profile to late8th.

Not a performance proxy

Dense early placements and single-block last make large updates without being the strongest models.

Takeaways

Placement is a design variable, not a detail

1Conclusions

  • Placement is a major, task-dependent factor; later blocks are generally strong and parameter-efficient.
  • At 8B, the transferred late8th separates from matched ParallelMLP on IFEval, SysBench and many-shot jailbreaking.
  • The route helps most with explicit constraints, multi-turn adherence and sustained many-shot attacks, not every form of extraction or injection.

→Future work

  • Other tasks, including privileged sources that are not system prompts.
  • Repeat sweeps across corpora, model families, scales and seeds; adversarial and preference-based training of the inserted blocks.

2Limitations

  • One frozen-backbone setup and one 50,000-example corpus: rankings may depend on corpus, optimization recipe, backbone family and freezing.
  • Each configuration was trained once, so variation across runs and initializations is not measured.
  • Placements swept only on Qwen2.5-1.5B. The 8B study changes model family, tokenizer, chat template and hyperparameters together, so it cannot isolate scale.
  • CAL does not uniformly beat the Base model on security, and is not a hard security boundary: it should not replace access control or input sanitization.
